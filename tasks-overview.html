web-access

基于 eze-is/web-access 改造成 Hermes 可直接使用的版本。核心不是“固定步骤”，而是：

1. 先定义目标与完成标准；

2. 用最便宜、最可信、最少侵入的方法拿证据；

3. 一旦静态层不够，就升级到共享 Chrome CDP；

4. 任务完成后清理自己创建的页面，不打扰用户现有 tab。

When to Use

以下场景优先触发本 skill：

  • 用户要求搜索信息、核实事实、读取网页内容。
  • 目标页面依赖动态渲染、滚动加载、登录态、真实浏览器环境。
  • 需要像人一样在网站内点击、填写、上传、截图、提取 DOM 数据。
  • 需要访问社交媒体、内容平台、管理后台等对静态抓取不友好的页面。
  • 需要决定该用 Hermes 内置 web_search / web_extract / browser_*，还是升级到共享 Chrome CDP。

Strategy Philosophy

像人一样思考，围绕结果决策，而不是死守预设步骤。

1. 明确目标：先定义什么算完成，需要获取什么信息或完成什么操作。

2. 选最短路径：优先用可信、成本低、侵入小的方法验证路径。

3. 用结果校正路线：搜索没命中、抽取质量差、DOM 不完整、登录墙挡路、交互被反爬，这些都是该切换方法的证据。

4. 到点就停：达到成功标准后停止，不为“看起来更完整”继续增加风险。

Hermes Tool Selection

优先级不是固定死板，而是按任务升级：

场景首选方式
找资料、发现候选来源、看当前事实web_search
已知 URL，提取正文/页面关键信息web_extract
已知 URL，要原始 HTML、meta、JSON-LD、header、接口响应terminal + curl
公开网页的简单交互、表单、可重复导航Hermes 内置 browser_*
登录态、动态渲染、站内搜索、社交平台、复杂交互、共享用户 Chrome 状态本 skill 的共享 Chrome CDP Proxy

补充原则：

  • 搜索引擎只负责“发现”，不负责“证明”。核实类任务必须回到一手来源。
  • 当 web_search / web_extract 多次尝试仍无质变，就不要死扛，应升级到官网、原始页面或 CDP。
  • browser_* 适合一般公开网页；一旦需要共享用户登录态、依赖真实日常 Chrome、或明显被静态/独立浏览器限制，就升级到共享 Chrome CDP。
  • Jina 可作为可选预处理层：https://r.jina.ai/http://目标URL，适合文章/文档/PDF，别把它当万能解析器。

Shared Chrome CDP Mode

前置检查（自动修复）

node ~/.hermes/skills/web-access/scripts/check-deps.mjs

macOS 上如果 Chrome 调试端口未开启，脚本会自动退出并重启 Chrome 来修复。

macOS 特例

Chrome 必须从 GUI 启动调试端口才有效。check-deps.mjs 已内置自动修复——用 osascript 退出 Chrome 再 open -a 重启。

手动启动：

# 先完全退出 Chrome（⌘Q），然后：
open -a "Google Chrome" --args --remote-debugging-port=19223

约束：

  • 使用用户日常 Chrome 配置（不新建空 profile），保留所有登录态和 cookie。
  • 默认不操作用户已打开 tab，只在自己创建的 tab 内操作。
  • 任务完成后关闭自己创建的 tab。

不稳定时的降级方案

如果 CDP 持续不可用，直接用 open <URL> 在用户 Chrome 打开页面，让用户手动操作。这不是失败，是策略切换。

CDP Proxy API

详细接口见：

  • references/cdp-api.md

常用入口：

  • GET /targets：列出当前 tab
  • GET /new?url=...：新建后台 tab
  • POST /eval?target=ID：执行 JS
  • POST /click?target=ID：JS 点击
  • POST /clickAt?target=ID：真实鼠标点击
  • POST /setFiles?target=ID：文件上传
  • GET /scroll?target=ID&direction=bottom：滚动触发懒加载
  • GET /screenshot?target=ID&file=/tmp/xxx.png：截图
  • GET /close?target=ID：关闭自己创建的 tab

Page Interaction Heuristics

  • 先观察页面结构，再决定动作；不要上来就盲点盲填。
  • 页面中很多内容可能“已加载但未展示”，优先用 /eval 看 DOM、属性、链接、图片 URL、视频状态。
  • 站内真实交互产生的链接通常比手工拼 URL 更可靠，因为它天然带着上下文参数。
  • 程序化操作快，但更像机器人；GUI 交互慢，但更像人。被拦时就切换，不要执念某一种方法。
  • 视频/图片任务优先提取原始媒体 URL；只有登录态媒体或必须看渲染结果时再截图/采帧。

Parallel / Subagent Use

多个彼此独立的调研目标可以并行，但在 Hermes 里要注意：

  • delegate_task 子 agent 不会自动继承这个 skill 的文本。
  • 所以分治时，必须把本 skill 里真正关键的浏览约束写进 context，不要只写“去加载 web-access skill”。
  • 只在任务彼此独立、每个子任务都有足够工作量时并行；简单单页查询不要强行分治。

  • 不要在同一种方法已经明显失效时机械重试。

  • 不要把 browser_* 和共享 Chrome CDP 混为一谈：前者是 Hermes 浏览器会话，后者是用户日常 Chrome。
  • 不要在 delegate_task 里假设子 agent 自动加载了本 skill。

Verification

  • 结论是否尽量回到一手来源。
  • 是否说明了所用路径（搜索 / 静态抽取 / 浏览器 / CDP）。
  • 若创建了后台 tab，是否已经关闭。
  • 若遇到 blocker，是否把 blocker 说清楚：登录缺失、权限不足、页面风控、内容不存在，还是访问方式不对。
