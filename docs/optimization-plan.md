# 成语肉鸽 · 墨韵 — 技术优化方案 v1

## 一、现状盘点

| 维度 | 现状 | 问题 |
|------|------|------|
| 架构 | 单文件 HTML 704 行，30 个函数全在全局 | 无法维护、无法测试、后续加功能互相踩 |
| 玩法 | 无尽爬塔 + 24 卡牌 + 6敌人 + Boss | 数值单薄，无事件/遗物/成长，策略深度浅 |
| 卡牌 | 24 张，8 类效果 | 效果靠 switch-case 硬编码，加卡=改代码 |
| 随机 | `Math.random()` 全局调用 | 不可复现、不可回放、无法做每日挑战 |
| 存档 | 仅 bestFloor 一个 localStorage key | 无局内存档、无局外成长 |
| 移动端 | 480x800 固定 canvas + touchStarted | 高分屏模糊、横屏/刘海屏不适配 |
| 变现 | 无 | 无广告位、无分享裂变、无内购 |

## 二、优化目标（按优先级）

1. **P0 架构重构** — 数据/逻辑/渲染分离，卡牌改数据驱动 → 后续所有功能的基石
2. **P1 玩法深度** — 遗物系统 + 随机事件层 + 局外成长（Roguelite 化）→ 留存的关键
3. **P2 种子随机** — 可复现 run + 每日挑战 → 分享裂变钩子
4. **P3 移动端/微信适配** — 高分屏 + 安全区 + 触控优化 → 变现的载体
5. **P4 变现接入** — 广告位/分享复活 → 目的

## 三、架构设计

### 3.1 模块拆分（单 HTML → 多文件，开发期分离，发布期合并）

```
idiom-roguelike/
├── index.html          # 入口（发布版：内联合并）
├── src/
│   ├── config.js       # 常量/调色板/难度曲线
│   ├── data/
│   │   ├── cards.js    # 卡牌数据（纯数据，24→60张）
│   │   ├── relics.js   # 遗物数据（新增）
│   │   └── enemies.js  # 敌人数据（6→12种）
│   ├── core/
│   │   ├── rng.js      # 种子随机数（mulberry32）
│   │   ├── deck.js     # 牌堆/弃牌/抽牌（已实现，抽成类）
│   │   ├── battle.js   # 回合状态机（untap→draw→main→end）
│   │   └── effects.js  # 效果解释器（数据驱动，替代switch）
│   ├── systems/
│   │   ├── relic.js    # 遗物系统
│   │   ├── events.js   # 随机事件层
│   │   ├── meta.js     # 局外成长/货币
│   │   └── save.js     # 存档（局内+局外双轨）
│   └── render/
│       ├── p5-scene.js # 场景绘制
│       ├── cards-ui.js # 卡牌UI
│       └── fx.js       # 特效/浮动数字/震动
└── build.py            # 合并发布脚本（inline所有js→单文件）
```

### 3.2 核心：效果解释器（最大的架构改进）

**现在**：`switch(card.type)` 硬编码，加一张新卡就要写新 case。

**目标**：卡牌 = 纯数据，效果 = 操作列表，由一个解释器统一执行：

```js
// data/cards.js — 卡牌就是数据
{ id:'hunyin_zhongzhi', name:'混水摸鱼', cost:1, type:'steal',
  effects: [
    { op:'steal_hp', amount:6 },
    { op:'steal_buff', chance:1 }
  ]}

// core/effects.js — 统一解释器
function resolve(op, target, ctx) {
  switch(op) {
    case 'steal_hp': /* 通用实现，任何卡复用 */ break;
    ...
  }
}
```

收益：加卡只写数据不写代码；遗物可以改效果参数（`damage+5`）而不碰逻辑。

### 3.3 种子随机（RNG 注入）

```js
// core/rng.js
const rng = mulberry32(runSeed);  // 每局一个种子
// 所有随机数走 rng()，禁止裸 Math.random()
```

收益：每日挑战（seed=日期）、回放 bug 复现、分享"我用了xxx种子打到第10层"。

### 3.4 双轨存档

```js
// 局内存档（每次战斗结束自动存）→ 死了可续
{ runSeed, floor, deck, relics, hp, score }

// 局外档案（永久）→ 成长货币
{ currency, unlocks, bestFloor, achievements, dailyStats }
```

### 3.5 微信小游戏适配（变现前最后一步）

- p5.js 在微信小游戏里 **不兼容**（需要 canvas 2D API 重写渲染层，或用微信适配库）
- **分两步走**：先做 Web 版打磨+裂变验证 → 数据好再迁移微信（渲染层换成 wx.createCanvas）

## 四、玩法设计（Roguelite 化）

### 4.1 遗物系统（一局内的永久强化）
- 每层胜利/事件获得 1 件遗物（玉佩/毛笔/砚台/印章…，成语文化主题）
- 遗物 = 效果修正器，挂在效果解释器上：`{ id:'jade', desc:'攻击+3', mod:{ attack_damage:+3 } }`

### 4.2 随机事件层
- 每层 30% 概率遇事件（遇隐士/闯破庙/解字谜…）
- 选择分支：拿钱/拿卡/拿遗物/赌 HP，三选一

### 4.3 局外成长（Meta）
- 每局结束按层数得「墨玉」（货币）
- 墨玉解锁：初始 HP+10、初始能量+1、起手多抽1张、新卡牌池解锁

### 4.4 每日挑战
- seed = YYYYMMDD，全服同图，排行榜（localStorage 假榜 → 后续接后端）

## 五、实施计划（增量，每步可玩）

| 阶段 | 内容 | 工作量 | 产出 |
|------|------|--------|------|
| **M1** | 模块化拆分 + 效果解释器（不新增玩法，纯重构） | 中 | 代码可维护，行为不变 |
| **M2** | 种子随机 + 双轨存档 | 小 | 可复现、可续局 |
| **M3** | 遗物系统 + 事件层 | 中 | 策略深度翻倍 |
| **M4** | 局外成长 + 每日挑战 | 中 | 留存+裂变 |
| **M5** | 移动端适配（高分屏/安全区） | 小 | 手机体验 |
| **M6** | 微信小游戏迁移 + 广告位 | 大 | 变现 |

**建议先做 M1+M2**（纯重构+基建，行为不变，风险低），做完评估再进 M3。

## 六、风险与对策

| 风险 | 对策 |
|------|------|
| 重构改坏现有玩法 | M1 纯重构后用回归测试清单（战斗→选牌→Boss→通关）验证 |
| 效果解释器设计过度 | 只抽象现有 24 张卡的 8 类效果，不预支未来 |
| p5 渲染层难拆 | 渲染函数保持纯函数（输入 state → 画），不耦合逻辑 |
| 微信迁移工作量大 | 先做 Web 验证玩法，数据说话再迁 |
