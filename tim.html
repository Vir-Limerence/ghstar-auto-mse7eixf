一、为什么预测"每个时间片的点击率"是正确的问题

白话

每个人打开手机的习惯不同：有人早上通勤刷快手，有人午休刷，有人睡前刷。如果你在用户通常不刷的时刻发推送，要么被忽略，要么被反感——甚至直接关闭通知权限。传统的推送时机研究只关注单条推送的最优时间，但现实中用户一天会收到多条推送，要优化的是一整天所有推送的整体效果。

白话类比：餐厅一天的服务节奏

一个餐厅经理不能只决定"中午12点要不要开门"——他需要知道一整天的客流分布：早餐6-8点人多、午餐11-1点爆满、下午2-5点没人、晚餐6-8点又爆满。同样，推送系统要知道"这个用户在早上8-9点的点击率多高"、"晚上10-11点的点击率多高"——然后按点击率高低分配推送配额。

现有方法的局限：

① 已有研究者利用传感器检测社交上下文（如"breakpoint"——用户暂停工作有闲暇的时刻），但只优化单条推送时机。

② 另一些方法预测整天动态CTR，但只用了上下文特征，没有建模用户的历史行为模式。

③ 前人都没有解决"全天多条推送的整体时机优化"——而这是工业系统的真实需求。

❌ 单条优化方法

只看"现在该不该发"，不考虑推送配额的整体分配。可能把所有推送都集中在"看起来最佳"的时间段，导致冗余。

✅ TIM + 全局优化

先预测每个时间片的CTR（天级行为建模），再在配额约束下全局求解最优分配——把推送分散到点击率高的多个时间段。

二、Temporal Attention Unit (TAU)：双层注意力挖行为模式

白话

一天被切成K个时间片（比如半小时一片，即48片）。对每个时间片，过去L天内用户在"同一时段"的历史行为（通知接收数、点击数、观看时长等）被收集起来。TAU用两层注意力提取模式：

① 第一层——"这个时段我过去是什么习惯"：看过去L天里同一时段的表现。

② 第二层——"相邻时段之间有啥关联"：如果早上8-9点点击率高，可能9-10点也高。

输入表示：对每个时间片k（k=1,...,K）收集过去L天的交互特征，形成K×L×d1的张量 X = (X1, X2, ..., XK)。特征包括：通知接收量、点击量、活跃时长、视频浏览数等。

第一层：目标注意力（Target Attention）

Query是目标日期类型（工作日/休息日），Key和Value是历史交互特征 + 历史日期类型：

o1k = softmax(q1K1⊤ / √d2) · V1
q1 = d⊤qWQ1
K1 = (Dh + Xk)WK1
V1 = (Dh + Xk)WV1

其中d_q是目标日期类型embedding，D_h是历史日期类型embedding（DTE）。日期类型分离是关键：工作日和休息日的行为模式可能完全不同——工作日晚上8点刷，休息日可能下午3点就在刷。

第二层：线性自注意力 + RoPE

K个时间片的o^1向量互相关注——用线性自注意力（无需softmax）和旋转位置编码（RoPE）：

Q2 = O1WQ2, K2 = O1WK2, V2 = O1WV2
O2 = (J + G(Q2)G(K2)⊤) V2

其中J是全1矩阵（相当于残差连接），G(·)是RoPE注入+ℓ2行归一化。线性自注意力的关键优势：无需softmax，计算复杂度从O(K²)降到O(K·d)——K=48时差异不大，但扩展性更好。

最终预测：每个时间片的o^2_k与用户上下文特征拼接后通过两层FC+ReLU+Sigmoid输出CTR预测 p_k：

pk = Sigmoid(FC(FC([o2k; context])))

三、全局推送时机优化：优雅的凸优化解法

白话

拿到每个时间片的CTR预测后，接下来要决定：在每天的推送配额q条的前提下，每个时间片该发几条？直觉是把推送集中在CTR最高的时间片——但这样会有一个问题：如果CTR最高的只有8:00-8:30这半小时，你把所有推送都挤在这里，用户会被连续轰炸，体验极差。

所以需要加一个正则化约束：不鼓励任何时间段太集中——让推送"均匀中带聚焦"。

优化问题：

minimizen −p⊤n + λ‖n‖22
subject to ‖n‖1 = q, ni ≥ 0, i = 1,...,K

n = (n1,...,nK) 是每个时间片的期望推送数，p = (p1,...,pK) 是预测CTR，q是每日配额。

两个关键项：

① −p⊤n：最大化总点击量（CTR高的时间段多分配）。

② λ‖n‖22：L2正则化惩罚集中分配——λ越大，推送越"均匀分散"。

拉格朗日函数：

L(n, φ, μ) = −p⊤n + λ‖n‖22 + φ(‖n‖1 − q) − μ⊤n

KKT条件推导：

2λni − pi + φ − μi = 0, i = 1,...,K
‖n‖1 = q, μ⊤n = 0, ni ≥ 0, μi ≥ 0

精简解：当μ = 0且满足约束时，有 n_i ∝ p_i，即 每个时间片的推送数量正比于其预测CTR。这个简洁的解意味着：

ni = q · pi / ‖p‖1

工程实现——累计CTR控制：

假设时间片s从t_{s-1}到t_s，CTR在片内均匀。在时刻t_{s-1}+Δ_t的期望推送累计量为：

P(ts−1 + Δt) = (Ph + Δt/T · ps) · q/‖p‖1

其中 P_h 是之前所有时间片的CTR之和。触发时的发送概率：

min( P(ts−1 + Δt) − H(ts−1 + Δt) , 1 )

其中 H(T) 是该时刻之前已发送的通知数。这个公式自然实现了"配额消耗成比例于CTR"——CTR高的时间段配额消耗快，触发频率高。

白话类比：按收入分配广告预算

一个广告主有q元预算，K个渠道的历史ROI分别是p_1,...,p_K。最优分配是按ROI比例投——ROI高的渠道多投，但不all-in一个渠道（因为有λ正则化防集中）。工程实现上，不是批量分配，而是"每次有机会投广告时，检查已花预算是否超比例，超过则跳过"。

四、RoPE和日期类型嵌入（DTE）的作用

白话

TAU有两个关键设计值得单独验证：RoPE（旋转位置编码）让模型知道"时间片8和9是相邻的"；DTE（日期类型嵌入）告诉模型今天是不是工作日。

可视化证据：注意力的"条纹"

论文提取了30天历史数据中的注意力分数热力图。在完整TIM中，注意力呈现清晰的"条纹模式"——工作日（0）和休息日（1）之间注意力分块，说明模型学会了区分"工作日的行为模式"和"休息日的行为模式"。而去掉DTE后（TIM_R——只有RoPE没有DTE），条纹消失——模型无法区分工作日和休息日，行为模式混在一起。

六、与 STEPS 的对比分析

STEPS

自触发闭环——系统自己决定"下次什么时候醒来检查"，不预设时间网格。用DT预测下次间隔。

TIM

固定时间网格——把一天切成K片，预测每片的CTR。用TAU提取历史行为模式。用凸优化求解全局分配。

七、总结

1. 切片预测 + 全局优化：TIM是首个同时解决"每片预测"和"全局分配"的推送时机系统——不是优化单条推送，而是全天多推送的整体最优。

2. TAU双层注意力：第一层目标注意力提取历史同期模式，第二层线性自注意力+RoPE融合相邻时段信息。日期类型嵌入区分工作日/休息日。

3. 凸优化解法：在配额约束下的最大化CTR问题有简洁闭式解：每片推送数正比于预测CTR。工程中用累计CTR控制实现流式决策。

4. RoPE + DTE的协同：单独RoPE提升0.21% AUC，单独DTE几乎无效果，两者结合提升0.93% AUC——时序位置感和周期区分的协同效应。

5. 交互特征的价值：从XGB(0.59 AUC)到MLP+交互特征(0.85 AUC)，交互特征贡献了提升量的大半——说明用户历史行为模式是预测CTR的最强信号。

6. 工业验证：快手在线A/B，DAU +0.1%, CTR +1.2%, 观看时长 +0.066%，关闭率中性——精准推送时机在不增加骚扰的前提下提升活跃度。
