一、推送时机为什么是个被低估的问题

白话

你每天收到约100条手机推送。如果推送在你忙的时候来——忽略了。如果在你刚打开手机干活时连续轰炸——烦了、关推送。TIM要解决的核心问题很简单也很致命：找到你"愿意看推送"的那个时刻。

这是一个系统级问题——不是单条推送的优化，而是一天中多条推送的整体排列。传统方法只看上下文特征（你当前在干嘛），不看你的行为模式（你每天几点习惯刷手机），且只优化单条推送。TIM是首个同时解决这两个gap的工作。

❌ 传统方法：只看上下文

判断"你手机在充电、WiFi连着、在室内"→推测你有空→推送。但没考虑你每天中午12点习惯刷10分钟快手的规律。

❌ 传统方法：只优化单条

每条推送独立判断该不该发。但今天5条配额，应该怎么分布在24小时？分到错误的时段=浪费+骚扰。

技术表述：移动通知时间优化存在两大空白：(1) 行为模式建模缺失——已有方法仅利用用户上下文特征（设备状态、环境），未建模用户长期行为规律；(2) 整体时序控制缺失——已有工作聚焦单通知的最佳时刻，缺乏对一天内多条通知整体发送时间的全局优化。TIM通过估计每一时间槽的slot-wise CTR，联合解决这两点。

二、TIM 模型架构：TAU + 两阶段注意力

白话

TIM的核心是Temporal Attention Unit (TAU)——一个两阶段注意力模块。第一阶段：对着同一个时间槽（比如"上午9-10点"），回顾过去30天你在此时段的行为，输出你对这个时段的"习惯画像"。第二阶段：让所有时段的画像互相"交流"——发现"你中午和下班后最活跃"这种跨时段规律。

TAU阶段1——目标注意力（沿天维度）：

o1k = softmax( qT1 K1 / √d2 ) V1

其中 q1 = dTqWQ1（目标日期类型嵌入），K1 = (Dh + Xk)WK1，V1 = (Dh + Xk)WV1。关键是Date Type Embedding (DTE)——把目标日期是工作日还是休息日的信号注入query和key，让模型区分工作日和休息日的行为差异。

TAU阶段2——线性自注意力 + RoPE：

O2 = (J + G(Q2)G(K2)T) V2

其中G(·)是先加RoPE再ℓ2行归一化，J是全1矩阵。这里用线性注意力（不用softmax）降低计算复杂度，适合K个时间槽的自交互。

三、两个关键设计：DTE 和 RoPE

DTE的核心洞察

你在工作日和休息日的行为模式完全不同——工作日早上通勤看、午休看、晚上看；休息日全天分散。如果模型不区分工作日/休息日，它会把两种模式混在一起，预测精度大打折扣。

RoPE的作用

在第二阶段自注意力中，RoPE（旋转位置编码）让模型感知时间槽之间的"距离"——早上9点和10点的行为接近，但和晚上8点的行为远。没有RoPE，模型不知道时间槽之间的远近关系。

注意力热力图的证据：

TIM的注意力热力图出现清晰的条纹模式——工作日和休息日形成明显分区。当去掉DTE后（TIMR），条纹消失，注意力分布变均匀。这证明DTE在引导模型关注正确的历史日期上起了关键作用。

四、整体发送控制：把配额最优地分布到一天

白话

TIM预测了每个时间槽的CTR后，下一个问题：每天q条推送配额，怎么分到K个时间槽？直觉是"CTR高的槽多发、CTR低的槽少发"。TIM把它建模成一个凸优化问题，用KKT条件推出最优解：每个槽的发送数正比于CTR，再加上一个平滑项防止集中轰炸。

凸优化形式化：

minimizen −pTn + λ‖n‖²2 s.t. ‖n‖1 = q, ni ≥ 0

其中 n = (n1,...,nK) 是各槽预期发送数，p = (p1,...,pK) 是预测CTR向量，q是每日配额。

−pTn 是期望点击数的相反数（最小化→最大化），λ‖n‖²2是正则项——防止所有推送集中在一个高CTR的槽里骚扰用户。

KKT条件求解：

2λ ni − pi + φ − μi = 0, ‖n‖1 = q, μTn = 0

整理得：ni = max(0, (pi − φ) / (2λ))。当所有ni > 0且λ = ‖p‖1/(2q)时，有ni ∝ pi，即每个槽的发送数正比于CTR。

在线实现——累积CTR控制：

假设槽s从ts−1到ts，CTR在该时段内均匀。时刻ts−1+Δt的期望发送数为：

P(ts−1+Δt) = (Ph + Δt/T · ps) · q/‖p‖1

当触发事件发生时，实际发送概率为：

min(P(ts−1+Δt) − H(ts−1+Δt), 1)

其中H(T)是时刻T前实际已发送数。这个公式的直观含义：如果"理想发送进度"领先于"实际发送进度"，就发；否则不发。

六、与STEPS的对比与关系

STEPS

"动态自触发"：三个Agent实时决策，系统自己决定下次何时醒来。连续时间、自适应间隔。

TIM

"静态时间段分配"：预先把一天切成K个槽，预测每个槽的CTR，用优化算法分配发送策略。

演进关系

TIM是STEPS的前身和基础——它奠定了"推送不仅要关注内容，还要关注时机"的核心洞察。但TIM的局限也很明显：

  • TIM的槽是固定划分的，不能自适应——如果用户在两个槽之间行为发生变化，TIM感知不到。
  • TIM只用slot-wise CTR做分配，没有建模序列决策中的长期影响——发一条推送后用户行为变化了，后续策略该怎么调整？

STEPS在TIM的基础上向前迈进了一大步：用自触发闭环替代固定槽，用Decision Transformer + Bellman RTG替代简单CTR预测 + 凸优化，实现真正的自适应、长期优化的推送时机决策。

链条：TIM（2024快手，时间槽CTR+优化分配）→ STEPS（2026字节，自触发闭环+三Agent协同）。TIM提出了"时机问题值得建模型"的命题，STEPS给出了更高维度的解答。

七、总结与创新点

1. 时间槽CTR预测：首次将推送时机优化形式化为"一天内所有时间槽的CTR预测问题"，实现整体而非逐条的优化。

2. TAU时序注意力单元：两阶段注意力（沿天的目标注意力 + 沿槽的自注意力），提取用户长期行为模式。

3. DTE日期类型嵌入：通过在工作日/休息日间做对比学习（注意力热力图验证），让模型区分两种行为模式。

4. 凸优化发送控制：将配额分配建模为带平滑项的凸优化，KKT条件得出ni ∝ pi的优雅策略并给出在线实现。

5. 工业验证：快手百万用户A/B实验，DAU+0.1%，CTR+1.2%，发送量和关闭率中性。

6. 学术影响：被STEPS、GenSeqNotif等后续工作广泛引用，是推送时序决策领域的奠基性工作之一。
