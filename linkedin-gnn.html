一、为什么要把多个产品揉成一张图？

白话

LinkedIn有Feed（帖子流）、Notification（通知）、Email（邮件）、Jobs（工作推荐）等多个产品。每个产品各自记录用户行为——你在Feed上看了一篇AI文章、在Email里点开了某个内推链接、在通知里忽略了某条新闻。传统做法：每个产品各建各的模型。

问题来了：Email里暴露的兴趣，通知系统完全不知道。就像你告诉咖啡师"我要冰美式"，三天后去隔壁寿司店，人家应该不用你再说一遍——但传统系统就是"说了等于白说"。

❌ 单域建图

通知领域自己建一张图、Feed领域自己建一张图、Email也建一张。用户在各域的行为像三本独立的日记，模型只读其中一本。

✅ 跨域统一建图

把通知、Feed、Email揉成一张大图，用户所有跨域行为都编码在图中，GNN消息传递时自然融合全域信号。

三大挑战

① 跨域信号碎片化：用户在Feed、Email、通知里的行为分散在多个数据孤岛，传统模型看不到全貌。
② 时序敏感性：通知的价值与"距用户上次活跃多久"强相关，刚打开过App就不该再打扰。
③ 多目标冲突：既要CTR高（短期），又要用户不关通知（长期），还要专业互动（深层价值）——三者经常打架。

二、统一图构建：8.6B 节点 × 1000亿边的超级异质图

白话

2.1 三种边类型：行为、关系、属性

第一类：Engagement Edges（行为边）

用户实际做过的动作。比如"M1点击了通知N"，是最直接的监督信号。每条行为边还带着时间戳，后续时序建模全靠它。

第二类：Affinity Edges（关系边）

行为边很稀疏——大多数人看了通知也不点。所以加关系边："M1长期关注M2发布的内容"形成双向边。这让信息可以在人与人之间流动，即使没有直接点击也能传播偏好。

第三类：Intrinsic Edges（属性边）

静态/缓慢变化的属性。比如"M1有职位头衔T"、"通知N提到了帖子P"。这些边让GNN理解"这个节点是干嘛的"，辅助推理。

Type 1: 点击/忽略
M2（成员）

节点特征设计：每个节点有稠密特征（BERT生成的文本嵌入，如帖子向量、通知向量）和离散特征（行业、资历、内容类型等one-hot）。这些初始状态喂给GNN做消息传递。

时序图化：给每条Engagement边加上时间戳，让后续的Transformer时序模块能按时间顺序建模行为序列。同时保证训练时不泄漏未来信息（只采样标签时间前的边）。

数据划分：图构建35天 → 训练数据14天 → 验证数据7天 → 测试7天。严格时序切分，模拟真实部署。

这1000亿条边不是凭空来的——大部分是affinity边（关系边），作用是把稀疏的click信号"扩散"到全图，让信息能在没有直接点击的节点间流动。

三、异质消息传递：GraphSAGE遇上R-GCN

白话

有了图，怎么从图上"学"东西？核心操作是消息传递。想象你在一个大型社交晚宴上，你想了解一个陌生人。你不会直接去问他——而是问他的朋友们："这人平时做什么？关注什么？" 每个朋友给你一句话，你把所有话加权汇总，形成对这个人的认知。

这就是GNN做的事。每个节点先把自己当前的"自我认知"（特征向量）发给邻居，邻居们把自己的特征传过来，然后聚合。问题是在异质图里，不同类型的边传递的信息含义完全不同——"点击过某条通知"跟"拥有某个职位头衔"能一样处理吗？

解法：扩展GraphSAGE + R-GCN，支持多节点类型 + 多边类型的异质消息传递。

m(l)u→v = f( h(l−1)u, h(l−1)v, t(u,v) )
h(l)v = σ( AGG({ m(l)u→v : u ∈ N(v) }) )

其中 t(u,v) 是边的类型（engagement/affinity/intrinsic），不同类型的边用不同的消息函数 f。AGG可以是均值、加权求和、或注意力机制。

为什么重要？"M1点击了通知N"这条边携带的信息，和"M1有职位头衔T"是完全不同的语义。如果共用同一个变换矩阵，就像用洗洁精洗水果和洗衣服一样——功能搞混了。边类型感知的消息传递确保每种关系有自己的专属权重。

双塔架构

GNN采用双塔架构：一塔专门编码"成员节点"（member encoder），另一塔编码"物品节点"（item encoder，这里的物品=通知）。两塔各自经过消息传递后，产出成员嵌入和通知嵌入，最后用点积或MLP预测点击概率。这个拆分还有个工程好处——在线只跑成员塔，物品塔离线算好存着。

四、时序建模：通知不是越新越好，而是"该新的时候新"

白话

链接预测（判断"这个用户会不会点这条通知"）如果只看静态图，就像你问"张三喜欢吃火锅吗"，但不知道他昨天刚吃完火锅。通知推荐特别依赖时效性——用户5分钟前刚打开过App，现在再推一条大概率骚扰；用户三天没登陆了，推一条关键动态可能让他回来。

LinkedIn的方法是：在标准消息传递之外，额外建一个时序聚合模块，专门捕捉"用户最近干了什么，以及什么时候干的"。

直觉类比

正常的消息传递就像看一个人的社交档案（朋友是谁、做什么工作、什么学历）。时序模块就像翻他的最近微信聊天记录（最近跟谁聊了、聊了什么、什么时候聊的）。两者结合起来，才知道"他现在可能对什么感兴趣"。

4.1 Time2Vec：让模型看懂钟表

直接把Unix时间戳喂给神经网络很难——大数字、非线性周期（周/日）。Time2Vec把时间戳映射到一个混合周期-线性表示空间：

Time2Vec(t)i =
{ ωi·t + φi,       if i = 0   （线性分量：捕捉"越近越重要"）
{ sin(ωi·t + φi),  if i > 0   （周期分量：捕捉"每天/每周模式"）

ωi 和 φi 是可学习参数。模型自动发现哪些频率最重要——比如某些ω学会捕捉"工作日vs周末"的24小时周期。

4.2 Transformer时序聚合

时序模块的完整流程：

① 对每个成员，采样最近K条通知交互（按时间排序）

② 每条交互的特征 = 通知邻居的Sage嵌入 + Time2Vec(交互时间戳)

③ 把所有K条拼接，送进Transformer Encoder（利用自注意力捕捉序列模式）

④ Transformer输出与标准消息传递的成员嵌入拼接，形成最终嵌入

hmember = hsage ∥ Transformer( Sage(N1) + T2V(t1), ..., Sage(NK) + T2V(tK) )

离线实验：加入时序建模后，通知pClick的AUC提升 +0.265%——在通知这种高时效领域，这个增益非常显著。

五、多任务学习（MMoE）：一箭三雕

白话

LinkedIn要预测的不只是"会不会点"（pClick）——还要预测"点了之后会不会做深度互动"（pPI: 点赞/评论/长时间阅读）。这两个目标相关但不同：一条"你的连接升职了"的通知，点击率可能一般，但点进去后用户很可能留言祝贺（高pPI）。相反，一条标题党通知点击率高，但点完秒关（低pPI）。

单独为每个目标训练一个模型，维护成本翻倍，还不能共享底层知识。多任务学习让一个模型同时输出多个预测，共享底层特征提取，各自保留专用头。

5.1 MMoE：专家各司其职

白话类比

一家医院有多个科室：内科、外科、儿科。每个病人来，挂号处（Gate）决定该找哪个科室，各科室的医生（Expert）各自诊断。有些病人需要多个科室会诊（Shared Expert）。

MMoE里，每个任务有自己的Gate（门控网络），决定"我这任务需要哪些专家的知识，各取多少"。各专家是独立的GNN编码器，Shared Expert是所有任务共享的。这样pClick任务可以侧重"点击模式专家"，pPI任务可以侧重"深度互动专家"，同时都能用共享的底层图表示。

MMoE的门控机制：

Gk(v) = Softmax( Wgk · N(v) )

N(v)是节点v通过节点编码器后的输出，Wgk 是任务k的可训练门控矩阵。Gk(v) 输出一个n维向量（n=专家数），表示每个专家的使用权重。

任务k的最终节点嵌入 = 各专家嵌入的加权和（门控权重控制），再送入任务k专属的MLP解码器：

ŷk(m,i) = MLPk( hkm, hki )

总损失 = 各任务的BCE损失加权求和：

L = Σk αk · Lk

六、生产架构：每天刷新，毫秒级推理

白话

GNN再牛，如果在线推理要10秒，也用不了。LinkedIn把GNN拆成离线重计算 + 在线快读取两段：每天凌晨用最新图重建所有成员的嵌入向量，存到特征库；白天用户打开App时，决策模型从特征库直接捞嵌入——毫秒级。

关键设计决策：

① 成员-物品塔拆分：成员塔离线跑，物品塔也离线算好。在线只需要做点积，不需要重跑GNN。训练需要32 GPU-天/轮，但在线推理几乎零成本。

② 每日刷新：嵌入每24小时更新一次。对大部分用户够用了——行为模式不会秒变。对极端实时需求，靠补充的轻量特征。

③ 跨产品复用：同一套成员嵌入可被Email排序、Feed推荐、工作推荐等所有产品线使用——一次计算，多点受益。

④ SPR集成点：GNN嵌入注入第二遍排序器（SPR），这是决定"最终发不发"的关键关口，嵌入在这里发挥最大价值。

说明

互操作畅想

十、总结：为什么这篇值得读

1. 跨域建图是最大贡献：把多个产品域揉成一张异质图，AUC暴涨8.089%。这验证了一个核心直觉——在超级App/平台时代，单域建模是"自己给自己盖天花板"。

2. 异质消息传递不可忽视：不同类型的边必须用不同的变换（engagement/affinity/intrinsic），混在一起会丢失语义。GraphSAGE + R-GCN的扩展方案简单但有效。

3. 时序建模锦上添花：Time2Vec + Transformer给pClick +0.265%。在通知这种时效敏感场景，这个增益不容小觑。

4. MMoE多任务学习解耦目标：点击率（短期）和专业互动（深层价值）两个矛盾目标，用门控专家各学各的。深层目标收益更大（+0.327% vs +0.063%），再次印证"难任务最需要共享知识"。

5. 工业级工程落地：15TB图、1000亿边、每日训练32 GPU-天、在线毫秒级推理——这不是纸面实验，是实打实的生产系统。拆双塔、特征库、SPR集成，每一环都是工程决策。

6. 关系型通知是GNN的杀手场景：关系型通知CTR +2.62%！社交图+通知=完美匹配。你的前同事升职了、你的连接发新贴了——这些信息的推荐天然是图问题。
