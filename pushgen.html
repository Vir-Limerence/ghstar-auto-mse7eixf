一、推送文案为什么值得用 LLM 写

白话

推送通知就几十个字，但写好了用户点开，写烂了用户直接关推送权限。传统做法是运营人员手写——但一个平台每天要发海量推送（不同用户不同内容不同场景），人工根本写不过来，只能套模板。模板文案千篇一律，用户看一眼就划走。

❌ 人工撰写

质量高但产能低。每天几百万条推送需要成千上万的运营，不现实。

❌ 模板填充

产能高但千篇一律。"你关注的XX更新了"每天发十几遍，用户麻木。

LLM 的优势

大语言模型可以低成本、大规模地生成多样化的推送文案。但带来两个新问题：① 风格不可控——LLM 可能写出过于正式、过于随意、或者完全不符合品牌调性的文案；② 质量不稳定——同一篇 LLM 可能写出惊艳的文案，也能写出废话。

二、PushGen 的双组件方案

白话

PushGen 就两个核心部件：一个管写什么风格（类别 Prompt），一个管挑哪个最好（奖励模型）。LLM 先生成一堆候选文案，然后奖励模型打分，选最高分的发。

三、可控类别 Prompt：给 LLM 戴上"风格面具"

白话

直接对 LLM 说"写一条推送"，它会随机发挥。有时候写得很正式像新闻联播，有时候写得太随意像朋友圈。PushGen 的做法是：先定义几种推送风格类别（幽默型、好奇心型、紧迫感型、情感共鸣型…），然后用类别标签控制 LLM 的输出方向。

类别 Prompt 结构：

Prompt = "[类别标签] + [视频元信息] + [用户兴趣标签] + [风格指示]"

例如对于"幽默型"推送：

[幽默类] 视频标题：XXX，作者：YYY
用户偏好：搞笑内容
请生成一条轻松幽默的推送文案，模仿脱口秀语气，15-25字

类别体系：PushGen 定义了多类推送风格，覆盖悬疑悬念、热点跟进、情感共鸣、幽默段子、实用干货等场景。每个类别有专门的风格指示模板，确保同类别的文案在调性上一致。

为什么这样做有效：LLM 擅长"角色扮演"。给定明确的风格指令后，模型会稳定地在该风格范围内创作，而不是在不同风格间随机跳变。这解决了品牌调性一致性的核心诉求。

多类别生成 + 后筛选

一次输入会生成多个类别的候选文案，然后奖励模型从中选出预期互动率最高的。既保证了风格多样性，又避免了"赌单枪"的风险。

四、奖励模型：用历史数据学会"预判爆款"

白话

LLM 生成 10 条候选，哪条最好？不能每次都上线 A/B 测试——太慢了。PushGen 训练了一个奖励模型，用历史推送的点击数据训练，让它学会"什么样的文案用户会点"。

训练目标：奖励模型 R(text, user, context) 预测给定用户和上下文下，某条推送文案的预期点击率（CTR）或互动概率。训练数据来自历史推送曝光日志：

Lreward = −[ y·logσ(R) + (1−y)·log(1−σ(R)) ]

其中 y = 1 表示用户点击，y = 0 表示未点击或滑走。

模型结构：基于预训练语言模型的 encoder，输入 = 推送文案 + 用户特征 + 上下文特征（时间、设备等），输出标量分数。

关键细节：

  • 训练数据包含位置偏差校正：同一条推送在不同时间/位置曝光率不同，需去偏。
  • 奖励模型不追求绝对 CTR 精度，只需要能相对排序——候选 A 比候选 B 好就行。
  • 上线后持续用新数据微调，形成飞轮效应：越用越准。

指标vs 模板基线

PushGen 在不骚扰用户的前提下提升点击，验证了"写好文案"本身就是一种用户体验优化。

奖励模型消融

筛选方式线上 CTR
随机选择基准
规则过滤（含关键词）小幅提升
奖励模型排序显著提升
奖励模型是 PushGen 的关键——光靠 LLM 生成不够，需要有质量的筛选器。

六、总结

1. LLM 生成推送：低成本、大规模替代人工撰写，文案多样性远超模板。

2. 类别 Prompt：用风格标签控制 LLM 输出方向，保证品牌调性一致性。

3. 奖励模型：从候选文案中自动筛选预期互动最高的，闭环优化。

4. 工业量产：已部署在快手推送系统，服务数亿用户，质量接近人工水平。

5. 核心洞察：推送内容的"写好"不是纯技术问题，而是"风格约束 + 效果筛选"的系统工程。
