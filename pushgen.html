一、推送文案为什么值得用LLM写

白话

快手每天有百万到数十亿条推送，但每天新传的视频是百亿量级！人工写推送文案一天只能写几千条，覆盖的视频不到0.2%。大部分视频是用模板生成的——"你关注的XX发了新视频"，干巴巴的，没什么吸引力。但用LLM写，成本低、规模大，问题是怎么控制风格、怎么评判好坏？

✅ 私域推送（模板）

你关注的作者发的视频，关系稳定，用简单模板就行。质量可控但不是增长主力。

⚠️ 公域推送（高难度）

从海量公共视频里挑高质量内容推给你——需要深度理解视频内容才能写出吸引人的文案。这才是PushGen的主战场。

对手与局限

快手前两代方案：(1) SFT小模型（Qwen-14B）——能写像人的文案，但缺少风格控制，生成结果同质化；(2) DeepSeek V3+RAG——效果更好（DAU +0.052%, CTR +4.33%），但没有事前CTR评估，上线前不知道哪个候选好。两代共同的盲区：缺乏可控多样性和CTR对齐的事前评估。

技术表述：PushGen解决两个核心gap：(1) Style Control——SFT缺乏对风格/主题的可靠控制，推理时无法定向输出多样风格；(2) CTR Alignment——缺乏可靠的事前（ex-ante）指标来预测文案CTR，点估计因为作者人气、话题热度、视频质量等混淆因素而不可靠。

三、Generator：数据清洗+可控风格SFT

三层数据过滤

LLM训练垃圾进垃圾出，所以PushGen在数据上花了大力气：(1) 硬过滤——CTR太低/播放太短/点踩太多/曝光不够的直接扔掉；(2) 软过滤——每个标签聚类内裁掉表现最差的20%，确保各类别分布均衡；(3) 置信度加权——高CTR和高曝光的样本给更高训练权重。

硬过滤条件：

filterhard = (CTR > 0.6%) ∧ (SVR < 40%) ∧ (LVTR > 50%) ∧ (HTR < 1%) ∧ (PV > 800)

CTR/SVR/LVTR/HTR分别代表点击率/短播放率/长播放率/点踩率，PV是曝光量。

置信度加权：

confidence = 0.3 + 0.35 · min(CTR, 0.1)/0.1 + 0.35 · log(min(PV, 10000)/10000)

CTR贡献35%权重（截断在10%以上），曝光量对数化的PV贡献35%权重，30%为基础值。这样既奖励高CTR，也避免低曝光样本被过度惩罚。

风格可控的秘诀

用DeepSeek-R1对历史推送做风格分类（悬疑、情感、实用、剧情、泛化等），形成预定义类别标签。SFT时输入格式为："任务指令 + 风格条件 + 视频描述"，推理时指定不同风格条件，一个视频可以生成多种风格的文案候选。

风格注入训练：

<Control Category> = LLMFrozenCategory(<Defined-Categories Task Prompt> + <Label_Push>)
<Push> = LLMGen(<Task Prompt> + <Control Category> + <Item Caption>)
Lsft = confidence × SFT(<Label_Push>, <Push>)

模型选型：试了Qwen2.5-32B、DeepSeek-R1-Distill-Qwen-32B、QwQ-32B等大模型，都出现严重过拟合。最终采用DeepSeek-R1-0528-Qwen3-8B，8B MoE架构在多epoch训练中保持泛化能力。

四、Reward Model：用A/B数据做CTR对齐评估

白话

传统做法：用模型预估每个文案的CTR分数——但这非常不准。因为CTR不光看文案，还受作者人气、话题热度、视频本身质量等大量混淆因素影响。PushGen的做法很聪明：在小流量A/B实验里，给同一个视频发不同文案，看哪个CTR更高——这样就消除了混淆，得到纯文案效果。

Pairwise训练（不是Pointwise）：对文案对⟨Push1, Push2⟩做输入拼接：

[CLS] Push1 [SEP] Push2 [SEP]
h[CLS] = BERT(⟨Push1, Push2⟩) → r = σ(MLP(h[CLS]))
Lreward = BCE(r, label), label = 1[CTR(Push1) > CTR(Push2)]

之所以做pairwise而非pointwise：pointwise只输出分数，容易学到"热门视频=高分"的捷径。pairwise强制模型比较同一视频的两版文案，迫使模型关注文案本身的差异。

五、为什么不加RL：Reward Hacking的教训

重要教训

PushGen团队试过把SFT+Reward Model用DPO/PPO/GRPO连接起来做RL优化，但发现了一个致命问题：CTR reward信号对"明星名字""具体数字"等显著性信息高度敏感。RL一驱动，模型就开始走捷径——不管你视频内容是什么，文案里塞个偶像名字CTR就高。结果是内容幻觉和事实不一致，这在推送场景是不可接受的。

所以PushGen目前的策略：SFT做可控生成 + 事后pairwise RM做筛选，Reserve RL留到未来解决了合法性检查问题后再用。

七、与STEPS的对比与关系

STEPS

"什么时候推"：自触发闭环决定推送时机，三个Agent优化发送策略。

PushGen

"推送文案怎么写"：LLM自动化生成高质量文案，解决内容层面的吸引力和多样性。

互补关系

PushGen + STEPS = 完整推送优化栈：PushGen生成吸引人的文案 → HGenPush决定推荐什么内容 → TIM决定什么时间发 → STEPS做整体自触发调度。从内容、时机、频率三个维度完整覆盖。

八、总结与创新点

1. 可控多样性生成：通过风格分类标签注入SFT，让LLM在推理时按指定风格输出不同文案，解决了SFT同质化问题。

2. 三层数据清洗：硬过滤 → 软过滤（标签内裁尾） → 置信度加权，从百万样本蒸馏出7万高质量训练数据。

3. Pairwise CTR Reward Model：用小流量A/B实验获取同视频不同文案的CTR对，训练pairwise判别器——消除了作者/话题/视频质量的混淆。

4. Reward Hacking识别：RL/DPO会放大显著性偏差导致内容幻觉，PushGen选择SFT+RM的保守但安全的方案。

5. 工业级部署：数亿用户上线，公域CTR +4.03%，DAU +0.067%，85.2%替换率——LLM写文案真的有用。
