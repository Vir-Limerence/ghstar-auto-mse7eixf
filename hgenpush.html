一、为什么需要异构生成式推送

白话

刷短视频时你不只看内容好不好，还会关注"这个作者值不值得关注"。传统推荐系统把"推荐视频"和"推荐作者"当成两个独立任务，分开做——但用户的需求是一体两面的。

另外，传统生成式推荐（如TIGER）用自回归（autoregressive）方式逐token生成——一次只吐一个token，跟打字一个字一个字蹦似的，推理效率太低，上线困难。

❌ 老方法一：单一类型推荐

TIGER等只用semantic ID推荐视频，完全没考虑"你关注哪个作者"这个需求，用户对作者有偏好但系统看不到。

❌ 老方法二：自回归逐token解码

一次forward pass只出一个token，3个codebook就要3轮推理。QPS直接被卡死，没法大规模上线。

技术表述：现有生成式推荐面临两大挑战：(1) 同质化生成——仅聚焦单一类型物品（如视频），无法联合推荐异构内容（视频+作者）；(2) 自回归瓶颈——主流semantic ID逐token自回归生成范式限制推理速度，消耗大量计算资源，阻碍生成式推荐模型在生产系统部署。

HGenPush重新定义问题：给定用户行为序列S（含feed行为Sfeed和push行为Spush），同时生成视频推荐结果和可信任作者推荐结果，且生成过程高效可部署。

二、HGenPush 整体架构

白话

HGenPush有三层核心模块：(1) Hybrid用户理解——把feed流和push流的行为融合起来理解你；(2) 双分支异构生成——视频推荐和作者推荐共享同一个理解结果，各自走自己的生成分支；(3) UCPA偏好对齐——用你真实的观看反馈（点赞、完播、转发）做RL优化，让模型不推"标题党"内容。

三、Hybrid 用户行为理解：四路序列融合

白话

你的行为不是孤立的——feed流里爱看什么 + push推送里点什么 + 最近在看什么 + 收到了什么推送，这四路信息合在一起才能完整刻画你。HGenPush用decoder-only架构把这几路序列一次性理解，输出两个压缩向量：一个给视频推荐用，一个给作者推荐用。

四路序列融合：

hf = [hlong; hshort; hclick; hsend; hstatic; h[cls]a; h[cls]v]

① hlong：长期feed行为序列（数月），编码稳定兴趣。每个视频包含 semantic ID + 作者ID + 话题标签 + 播放时长。

② hshort：短期feed行为序列（近期），捕捉兴趣漂移。

③ hclick：push点击序列，反映用户对推送内容的反应模式（加notification type特征）。

④ hsend：push发送序列，构建上下文避免重复推荐。

⑤ hstatic：静态特征（年龄、性别），作为稀疏行为时的稳定信号。

两个[cls] token h[cls]v和h[cls]a分别承载视频和作者推荐分支的全局视角。

为什么选Decoder-Only？对比实验：Encoder-Decoder架构（0.026B参数）vs Decoder-Only（0.016B参数），decoder-only在参数少38%的情况下达到同等的HitRate@100（0.3432 vs 0.3400），且推理延迟更低。原因是decoder-only统一处理所有序列，不需要encoder-decoder间传递的额外开销。

四、Chained-MTP：链式多Token并行预测

核心创新

这是HGenPush最漂亮的设计。传统自回归生成：第2个token要等第1个token出来才能算——串行，慢。Parallel-MTP：所有token并行算——快，但完全丢了token之间的依赖关系，HitRate暴跌。Chained-MTP取两者精华：用前序token的embedding累积传递依赖，但用并行FFN同时输出所有token。

Chained-MTP公式：

pskvt = softmax(FFN(k)(h'[cls]v + Σj<k Emb(j)(sjvt))) · skvt

关键设计：(1) h'[cls]v作为稳定兴趣锚点——全局上下文不变，防止"生成着生成着跑偏了"；(2) 累积前序embedding ΣEmb——用前一个token的语义信息调节当前token的生成，保持层级依赖；(3) 并行FFN——所有token的FFN可以并行计算，不需要等上一个token。

Chained-MTP效果与DeepSeek-MTP持平（只差0.4%），但吞吐高出33.86%。Parallel-MTP虽然最快但效果腰斩——证明语义依赖不能丢，但可以通过embedding累积而非串行计算来维持。

五、作者推荐分支：行为对齐 + 混合语义ID

白话

作者推荐的核心难点：两个同类作者你看哪个？光看内容特征区分不出来。比如两个美妆博主，内容标签差不多，但你只关注其中一个——这个偏好体现在你的行为数据里（你反复点她的视频），但不在内容embedding里。

HGenPush的做法：拿你的行为数据和作者特征做对比学习（InfoNCE），把"你喜欢谁"这个信号压缩到作者的semantic ID里，然后生成时直接输出"你喜欢的作者+他最新的视频"。

行为表征对齐（InfoNCE）：

Lalign = −1/B · Σb log [exp(cos(hub, hab)/τ) / Σb' exp(cos(hub, hab')/τ)]

先把用户兴趣表征h'[cls]a和作者特征映射到统一空间，再用InfoNCE拉近正样本（你点过的作者）。这样作者semantic ID里就嵌入了"双向受众信息"——不仅知道作者是谁，还知道谁喜欢这类作者。

混合Semantic ID：smt = (s1at, s2at, s1vt)，把2个作者codebook + 1个视频第一层codebook拼在一起，实现"先推荐作者，再推荐该作者的视频"的层级化生成。

作者codebook用SimVQ策略防止codebook坍塌，训练时同步更新：

Lcodebook = 1/B · Σb Σl ∥sg(rlab) − cslabl∥²

六、UCPA：点击不够，要看真消费

关键问题

模型靠点击数据训练，会学到什么？标题党。因为只要诱导你点进去就算"成功"——至于你进去后一秒划走还是看完，模型不关心。UCPA模块把真实的消费反馈信号（完播、点赞、分享、举报）做成奖励，用RL让模型生成高质量内容。

奖励信号设计：

rg = rg + 2 (有效播放/进主页/评论停留) | +1 (点赞/关注/分享/评论) | −2 (短播放) | −5 (点踩) | −10 (举报)

累计加分制：高质量行为多给分，负反馈重重扣分。所有视频在group内做归一化计算相对优势：

Âg = (rg − mean(R)) / std(R)

GSISPO算法：结合GSPO的序列级优化（避免token级优化破坏语义完整性）+ CISPO的裁剪重要性采样权重（保留小众高价值行为的梯度信号）：

LGSISPO(θ) = −1/G · Σg sg(wg(θ)) · Âg · log πθ(svg | h'[cls]v)
wg(θ) = clip( exp(1/Lv Σk log πθ/πθold), 1−ε, 1+ε )

八、与STEPS的对比与关系

STEPS

关注"什么时候推送"：自触发闭环，三个Agent决定推送时机和频率。核心是时间决策。

HGenPush

关注"推送什么内容"：端到端生成式推荐，从用户行为直接生成高质量视频+作者推荐。核心是内容生成。

互补关系

STEPS和HGenPush解决推送系统的不同环节：STEPS管"什么时候推、推不推"，HGenPush管"推什么内容"。两者组合在一起就是完整的智能推送系统——HGenPush生成高质量候选内容，STEPS决定在最佳时机发送。

共同趋势：都采用end-to-end学习替代多阶段分步优化，都不依赖人工规则，都在大规模工业场景上线验证。

九、总结与创新点

1. 异构生成式推荐：首次在统一架构中同时生成视频和作者推荐，覆盖"内容质量+信任关系"双重用户需求。

2. Chained-MTP：用embedding累积传递语义依赖 + 并行FFN生成，效果持平自回归但吞吐提升33.86%。

3. 行为对齐作者编码：用InfoNCE对比学习把用户行为偏好注入作者semantic ID，解决"同类作者无法区分"的问题。

4. GSISPO偏好对齐：序列级RL优化+裁剪重要性采样，用真实消费反馈替代简单点击信号，全面提升内容质量。

5. Scaling Law验证：0.016B→0.064B→0.170B持续正向，MoE扩展有效。

6. 工业级部署：快手推送系统全量上线，DAU +0.181%，生成候选绕过预排序直通精排。
