一、为什么需要异构生成式推送

白话

刷短视频时，你既关心"内容好不好看"，也关心"这人靠不靠谱"。一个你信任的创作者发的内容，哪怕题材不熟悉你也愿意点开。但现有的 AI 推荐系统只能推荐单一类型——要么推荐视频，要么推荐作者，做不到两者兼顾。而且它们用自回归方式一个一个 token 地生成，太慢了。

❌ 单类型推荐

只能推荐视频或只能推荐作者。用户"想看好内容"和"想关注好作者"是两个需求，分开满足效率低。

❌ 自回归生成

一次生成一个 token，N 个 token 就要 N 轮推理。工业场景下用户量太大，延迟扛不住。

关键洞察

传统生成式推荐把物品编码成语义 ID（semantic ID），然后像 GPT 写作文一样从左到右自回归生成。但推荐任务和文本生成不一样——推荐 token 之间没有强因果依赖，完全可以一次性并行预测所有 token。

技术表述：短视频平台的推送系统需要同时满足用户对高质量内容和可信作者的双重需求。现有生成式推荐方法（如 TIGER、P5）仅生成单一类型的推荐内容，且采用自回归范式逐个生成语义 ID，效率低下。HGenPush 首次将异构生成（heterogeneous generation）引入推送推荐——在一个统一框架内同时生成视频推荐和作者推荐。

三、模块一：混合用户行为理解

白话

你在快手上的行为不是孤立的——你搜过什么、点赞过谁、在哪个视频上多看了一会儿，这些都有关系。传统方法只看单一维度的历史，比如只看"点过哪些视频"，但忽略了搜索意图和作者偏好。

设计：混合用户行为理解模块整合多场景（搜索、推荐流、关注流）和多视角（点击、点赞、分享、完播、搜索词、关注关系）的行为数据。通过跨场景的特征交叉网络，将不同粒度的行为信号统一成一个稠密向量，作为后续生成模块的输入。

关键优势：不是把所有行为简单拼一起，而是学习行为之间的交互——比如"搜了某关键词然后点赞了某个视频"这样的序列关系。

四、模块二：双分支异构生成

白话

这是 HGenPush 的核心创新：一个模型同时输出两条推荐——"推荐这个视频"和"推荐这个作者"。两条路共享对用户的理解（用户喜欢什么），但各自走不同的专家网络来生成各自的语义 ID。

架构细节：双分支生成模块共享底层用户表征编码器，但使用独立的生成头（generation head）：

P(video) = Head_video(E_user)
P(author) = Head_author(E_user)

视频和作者各自有独立的语义 ID 空间（RQ-VAE 量化的码本），两个头的输出分别对应视频码本和作者码本。训练时两个损失联合优化：

L = L_video + α·L_author

α 是平衡系数。两种推荐共享对用户的深层理解，互相增强——从你关注的作者中推断你喜欢的视频类型，反之亦然。

为什么不用一条路同时输出？

视频和作者的语义空间完全不同。视频关注的是内容主题、风格、时长；作者关注的是可信度、垂直领域、更新频率。混合在一起会让模型在两个任务之间左右摇摆（互斥梯度），分开走各自的专家网络反而各精其业。

五、模块三：轻量多 Token 并行预测

白话

自回归生成就像你写作文一个一个写字——写完第一个字才知道第二个字写什么。但推荐场景里，视频的第1层语义ID和第2层语义ID 没有严格的先后因果关系——完全可以同时预测。HGenPush 把 N 个 token 一次并行输出，推理速度提升 N 倍。

技术细节：传统自回归范式逐个生成语义 ID：

P(c₁, c₂, ..., c_K | u) = Πk=1K P(c_k | c_{< k}, u)

HGenPush 改为并行多 token 预测（multi-token prediction）：

P(c₁, c₂, ..., c_K | u) ≈ Πk=1K P(c_k | u)

即每个位置独立预测，K 个 token 一次推理完成。虽然理论上损失了 token 间的条件依赖，但实验表明推荐场景下这一信息损失几乎不影响效果，而推理延迟大幅降低。

实现上，用独立的轻量预测头（轻量 MLP）挂载在共享编码器上，每个预测头负责一个 token 位置，所有头并行计算。

六、模块四：消费偏好对齐

白话

模型生成的推荐不一定符合你的口味——可能给你推了你从来不看的类型。这个模块用你真实的反馈（点击了没、看了多久）作为奖励信号，微调模型往你真正喜欢的方向走。类似 RLHF 但更轻量。

方法：用户消费偏好对齐模块将用户反馈（点击、观看时长、有效播放、分享等）转化为奖励信号 R(u, item)，然后通过策略梯度方法微调生成模型：

∇θ J = E[ R(u, item) · ∇θ log Pθ(item | u) ]

这本质是一种离线策略优化：用已收集的曝光日志作为行为数据，对生成模型做偏好对齐，使之偏向生成高互动率的推荐。由于推荐 token 空间有限（码本大小可控），不需要像 LLM 那样用复杂的 PPO，简单的 REINFORCE 就够用。

八、总结

1. 异构生成：首次在推送场景统一生成视频和作者两类推荐，一个模型覆盖双需求。

2. 多 token 并行：抛弃自回归，K 个 token 一次并行预测，推理效率大幅提升。

3. 多场景行为融合：搜索+推荐流+关注流多视角行为整合，精准画像。

4. 偏好对齐：用用户真实反馈做离线微调，生成更贴合口味的推荐。

5. 工业验证：快手推送系统全量部署，DAU +0.181%，千万级用户受益。
