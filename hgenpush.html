一、为什么要同时推荐视频和作者

白话

你打开快手，不光想看好视频，还想关注好作者。比如你刷到一个篮球教学视频觉得不错，但如果还能告诉你"这个作者还有大量类似的优质教程，关注他不亏"，那你留存的概率就大很多。视频解决"这次看什么"，作者解决"以后看什么"。

老方法的两大痛点

① 只能推一种东西：TIGER、OneRec这些生成式推荐模型虽然已经用上了Transformer直接生成推荐结果，但它们只能推"同一种类型"的内容——要么全推视频，要么全推商品。视频和作者就像油和水，没法用一个锅炒。

② 自回归太慢：传统方法生成语义ID必须一个token接一个token地解码，就像一个人只能一步一步走路，不能跑。对于工业级系统，每次推理多轮前向传播，QPS根本扛不住。

技术表述：现有生成式推荐面临两个核心挑战：

① 同质化困境：TIGER[12]、OneRec[3]等方法专注于单类型物品推荐（如视频或商品），无法在统一框架内联合处理异质内容（videos + authors）。

② 推理效率瓶颈：主流的自回归语义ID生成需要多轮解码（每个codebook一层需要一次forward），限制了在线服务的吞吐量。在大规模推送场景下，延迟和成本都成为制约因素。

❌ TIGER / OneRec

只能推一种类型，自回归解码慢。语义ID依靠RQ-VAE学物品内容，但无法区分"用户喜欢这个作者"和"用户喜欢这个类型"。

✅ HGenPush

视频+作者双分支异构生成，Chained-MTP一次推理产出全部语义ID。行为对齐让作者编码学会"用户偏好"而不是"通用特征"。

二、HGenPush 整体架构：三合一流水线

白话

想象一条自动化生产线：原料（用户行为序列）进入第一个车间，工人把所有历史行为——长期看什么、短期看什么、点了什么推送、推送了啥——全部汇总成一份用户画像。然后这份画像进入两个并行车间：一个车间专门生产"推荐什么视频"，另一个车间专门生产"推荐哪个作者"，两个车间同时开工。最后还有一个质检车间，根据用户消费反馈来奖励/惩罚前面的车间。

HGenPush是一个decoder-only的端到端架构，包含三个核心模块：

① Hybrid User Behavior Understanding（混合行为理解）：融合多场景多视角的用户行为序列。包括App内Feed的长短期行为、推送点击序列、推送发送序列，以及用户静态特征（性别、年龄）。输出两个特殊token：[cls]_a（给作者分支）和[cls]_v（给视频分支）。

② Heterogeneous Generative Recommendation（异质生成推荐）：视频分支用Chained-MTP并行生成语义ID，作者分支通过行为对齐将作者编码离散化为语义ID后生成。

③ User Consumption Preference Alignment（消费偏好对齐）：基于RLVR范式，用推送后用户的真实消费行为（有效播放、点赞、转发等）作为奖励信号，通过GSISPO算法优化模型。

三、混合行为理解：像侦探一样拼凑用户画像

白话

理解一个用户，不能只看他在快手App里刷了啥，还得看他收到推送后点了哪些。就好比你认识一个人，不仅要知道他平时爱逛什么店（Feed行为），还要知道他收到促销短信后有没有进店（推送行为），甚至他最近一个月和最近三天的兴趣变化也不同。

3.1 多视角行为融合：四面八方的信号都收进来

白话类比：警察办案

警察办案不会只看一个监控摄像头，而是调取所有相关录像：长期监控（这个人在这个区域出现了多久）、短期监控（最近几分钟去了哪）、报案记录（之前有没有类似行为）、案发现场环境（周围是商业区还是居民区）。每个摄像头看到的信息拼在一起，才是一个完整的嫌疑人画像。

四类行为序列 + 静态特征：

① 长期Feed序列 S_long：表达用户稳定、长期的内容偏好。每个视频用语义ID + 作者ID + 话题标签 + 播放时长四个维度表示。

hiv_long = σ(Dense([esemantic; eaid; etag; eplaytime]))

② 短期Feed序列 S_short：捕捉用户近期兴趣漂移，构建方式同上。

③ 推送点击序列 S_click：反映用户对推送通知的偏好模式，引入通知类型(type)特征区分不同推送内容。

hiv_click = σ(Dense([esemantic; eaid; etype]))

④ 推送发送序列 S_send：构建上下文，防止模型推荐已发送过的内容，增强推荐合理性。

⑤ 静态特征 h_static：作为"稳定器"，在行为稀疏时提供可靠信号。

hstatic = σ(Dense([eage; egender; ...]))

最终拼接：

hf = [hlong; hshort; hclick; hsend; hstatic; h[cls]_a; h[cls]_v]

其中 h[cls]_a 和 h[cls]_v 是两个可学习的特殊token，分别作为作者分支和视频分支的"起手式"。

3.2 Decoder-Only主干：16层精心设计的Transformer

白话类比：层层蒸馏

就像做酱油，不是一次就成，而是经过多次发酵——每一层attention重新提炼一次，16层下来，最开始的原始行为数据被反复"蒸馏"，最终浓缩成两部分精华：一个叫"[cls]_v"（视频分支的全局理解），一个叫"[cls]_a"（作者分支的全局理解）。

每个block的计算流程：

h(l+1)attn = CausalSelfAttn(RMSNorm(h(l)))
h(l+1)add = h(l) + h(l+1)attn
h(l+1) = h(l+1)add + FFNSwiGLU(RMSNorm(h(l+1)add))

使用RMSNorm增强训练稳定性，SwiGLU FFN提升表达能力。16层堆叠后输出最终表示 h' = {h'[cls]_a, h'[cls]_v}。

两个[cls] token处于序列末尾，因果注意力让它们能看到前面所有token，所以它们的编码不仅包含了静态特征，还综合了全部行为序列——形成带有时序感知的兴趣表示。

四、双分支异构生成：两个车间并行流水

白话

拿到用户画像后，两个车间同时开工。视频车间要回答"推哪个视频"，作者车间要回答"推哪个作者"——但最终落地时，推作者也是推"这个作者的某个视频"，所以作者分支生成的语义ID里既包含作者信息，也包含视频信息。

4.1 视频分支：Chained-MTP——告别自回归的一次性并行生成

白话类比：比赛接力 vs 并列冲刺

传统自回归就像接力赛：第一棒跑完，第二棒才能接棒起跑——必须等前一个token生成完毕才能生成下一个。而Chained-MTP就像所有人都站在起跑线上同时出发，但每个人手里拿着一张"前棒选手的参考数据"——不是真等，而是提前知道别人大概会怎么跑。结果就是：几乎一样快，但速度提升了34%。

核心公式：目标视频 v_t 的语义ID为 sv_t = (s1v_t, s2v_t, ..., sL_vv_t)。对第k个token：

pskv_t = softmax(FFN(k)(h'[cls]_v + Σj<k Emb(j)(sjv_t)))

关键设计：

① h'[cls]_v 作为稳定锚点：用户兴趣表示保持不变，防止"兴趣漂移"——不会因为先预测了某个粗粒度token就偏离了用户真实兴趣。

② 累积嵌入 ΣEmb(s^{<k})：前序token的embedding逐层累加到当前预测中，建模"第一层token影响第二层"的语义依赖——不是完全独立，而是"知道前文但不依赖前文推理"。

③ 并行FFN：L_v 个独立的FFN头同时计算所有层的概率，推理只需一次前向传播。

Lv-MTP = −1/B · Σb=1B Σk=1L_v log(pskv_b)
方法HitRate@100设备最大QPS说明
Parallel-MTP（完全独立预测）0.11502.40k最快但完全丧失语义依赖
DeepSeek-MTP（层级Transformer）0.39541.27k最好效果但减速47%
Chained-MTP0.39151.70k效果接近最优，速度+34%
Chained-MTP在效果上仅比DeepSeek-MTP低0.99%，但QPS高33.86%——用很小的精度代价换来了巨大的效率提升，这正是工业级系统最看重的trade-off。

4.2 作者分支：用行为"对齐"作者画像

白话类比：相亲匹配

传统的作者编码就像只看了相亲对象的简历（作者的内容特征），但简历没法告诉你"这个人适合什么类型的人"。行为对齐就像是让相亲平台统计"什么样的人喜欢这个作者"——如果发现喜欢这个作者的用户画像都是"喜欢篮球的25岁男性"，那作者编码就有了"受众偏好"的维度。

为什么只用内容特征不够？

两个美食作者，内容上高度相似（都有炒菜视频），但用户就是偏爱其中一个。这种偏好不能从内容推断，只能从用户行为中挖掘——"画风"、"人设"、"口播风格"这些东西无法被多模态embedding有效捕获，但用户的点击和关注行为会忠实记录。

三步走：

Step 1 — 行为对齐（InfoNCE损失）：

Lalign = −1/B · Σb=1B log( exp(cos(hu_b, ha_b)/τ) / Σb'=1B exp(cos(hu_b, ha_{b'})/τ) )

将用户兴趣表示 h_u 和作者特征表示 h_a 投影到统一空间后，用InfoNCE对比损失拉近"真实用户-作者对"，推远"随机配对"。这让作者编码学会了"谁喜欢我"这个双向信号。

Step 2 — 作者语义ID离散化（RQ-Kmeans + SimVQ）：

sla_t = argminn ‖rla_t − cln‖22
rl+1a_t = rla_t − clsla_t

对齐后的作者embedding通过RQ-Kmeans逐层量化，每层取最近质心后计算残差传给下一层。L_a=2层，每层8192个质心。代码本损失：

Lcodebook = 1/B · Σb=1B Σl=1L_a ‖sg(rla_b) − clsla_b‖22

Step 3 — 混合语义ID生成：

作者分支最终推荐的还是视频（作者的最新/最热视频），所以生成目标是混合语义ID：

sm_t = (s1a_t, s2a_t, ..., sL_aa_t, s1v_t)

前L_a个token定位作者，最后一层token定位该作者的某个视频——先选作者再选作品，Chained-MTP同样适用。

La-MTP = −1/B · Σb=1B Σx=1L_m log(psxm_b)

五、消费偏好对齐：让模型学会分辨"好内容"和"标题党"

白话

如果只看点击率，标题党一定能赢——"震惊！这个视频让你怀疑人生"肯定比"家常菜做法教程"点击率高。但用户点进去看两秒就走了，甚至反感。所以需要引入点击之后的消费信号：有效播放、点赞、关注、转发、甚至举报——用这些"真反馈"告诉模型：别光追求点击，要看用户满意度。

白话类比：餐厅评分

只看"进店人数"（点击率）评价餐厅是不行的——网红店门口天天排队，但吃完都骂。真正的评价要看吃完之后的反应：是否回头（有效播放）、是否拍照发朋友圈（转发）、是否给好评（点赞）、是否再也不来（dislike）、是否投诉（举报）。HGenPush的奖励信号就是这套"吃完后"的评分体系。

5.1 奖励信号：量化用户的"真满意"

定义推送点击后session内消费的G个视频V = {v_1, ..., v_G}，对每个视频按规则打分：

用户行为奖励含义
有效播放 | 进入主页 | 评论停留+2深度消费
点赞 | 关注 | 转发 | 评论+1正向互动
短播（快速划过）−2不感兴趣
不感兴趣−5明确反感
举报−10严重负面

每个视频累加所有匹配条件的奖励得 r_g。然后做组内归一化得到相对优势：

Âg = (rg − mean(r1,...,rG)) / std(r1,...,rG)

5.2 GSISPO：融合GSPO和CISPO的序列级优化

白话类比：给流水线质检打分

常规的token级优化就像检查每个零件是否合格（每个语义token是否正确），但这会破坏"零件之间的配合关系"（语义连贯性）。GSISPO的做法是整个产品组装好后整体打分（序列级奖励），同时用重要性采样的"限幅器"防止梯度爆炸——就像质检员既要看成品，又不能因为一个次品就把整条产线停产。

GSISPO优化目标：

LGSISPO(θ) = −1/G · Σg=1G sg(wg(θ)) · Âg · log πθ(sv_g | h'[cls]_v)

其中 w_g(θ) 是序列级重要性采样权重：

wg(θ)' = (πθ(sv_g|h'[cls]_v) / πθ_old(sv_g|h'[cls]_v))1/L_v
wg(θ) = clip(wg(θ)', 1−ε, 1+ε)

三个关键设计：

① 序列级概率：避免token级优化导致的"语义碎片化"——GSPO思想。

② 重要性采样裁剪：把clip操作从梯度移到权重上，保留小众但高价值行为的梯度信号——CISPO思想。

③ 无需KL散度：因为L_v-MTP还在同时训练，天然提供稳定性约束。

总损失：

七、与 STEPS 的对比分析

STEPS

聚焦"何时推送"的时序决策问题。三个智能体（规划师、执行官、守门员）协作决定push timing，但不涉及"推什么内容"的生成。

HGenPush

聚焦"推什么内容"的生成问题。用生成式模型同时产出视频和作者的语义ID，决定push content，但不优化timing。

维度STEPSHGenPush
核心问题何时推送 (when)推什么内容 (what)
方法范式强化学习（自触发DT）生成式推荐 + RL对齐
输出空间推送/不推送 + 下次间隔视频语义ID + 作者语义ID
推理效率优化守门员过滤（3层MLP）Chained-MTP并行生成
奖励信号活跃天数 + 推送关闭率消费行为（播放、点赞、转发）
平台抖音（字节）快手
DAU增益+0.28%+0.181%
STEPS和HGenPush是推送系统这枚硬币的两面：STEPS管"什么时候发"，HGenPush管"发什么内容"。两者可以叠加部署——用STEPS决定timing + 用HGenPush决定content，形成完整的推送优化管线。

八、总结

1. 异质生成推荐：首个在生成式推荐框架中同时处理视频和作者两种异质内容的系统，视频满足"内容需求"，作者满足"信任/关注需求"。

2. Chained-MTP：用"稳定锚点+累积嵌入"替代自回归，一次推理并行产出全部语义token，QPS比DeepSeek-MTP高34%，效果仅低1%。

3. 行为对齐：通过InfoNCE将作者编码与用户兴趣对齐，让作者推荐不再依赖通用内容特征，而是学会"谁喜欢我"的双向信号。

4. GSISPO：融合GSPO（序列级优化防语义碎片）和CISPO（梯度裁剪保留小众信号），在不损害主任务的前提下让模型学会推"好内容"。

5. 工业级验证：快手4亿日活部署，DAU +0.181%, CTR +1.577%, 转发率 +7.57%。Scaling Law验证到0.17B参数仍有效。
